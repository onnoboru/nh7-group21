# GrandPals

`idea_a.md`〜`idea_e.md` と `idea_like.md` をもとに、子どもと高齢者の交流をゲームとペットの成長から育てる Web アプリです。アプリ内の画面・メッセージは英語、説明文書は日本語です。

まずローカルで試して、そのまま GitHub Pages や CPU サーバーで共有できる構成にしています。**実際の2人が1台の端末を囲んで使う対面ゲーム**と、週ごとの質問・返事で育つペットのローカルジャーニー、架空の人物との交流を試す Community demo を用意しています。データはブラウザー内に保存され、離れた端末との通信・同期は行いません。

## 起動する

Node.js 22 以上がある環境で、このディレクトリから実行します。

```bash
node scripts/serve.mjs
```

ブラウザーで **http://127.0.0.1:4173** を開きます。終了は `Ctrl+C` です。ポートが使われている場合は変更できます。

```bash
node scripts/serve.mjs --port 8080
```

`npm install`、グローバルパッケージ、Python の仮想環境、GPU、API キーは不要です。既存の Node.js の標準機能だけを使い、ホームディレクトリへの設定追加やサービス登録は行いません。`dist/` は生成物ではなくアプリのソースそのもので、ビルドも不要です。

Node.js を使わず、既存の Python 3 で配信することもできます。

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

ES Modules を使っているため、`index.html` のダブルクリックではなく HTTP サーバー経由で開いてください。

## 2人で対面利用する

1. 同じスマートフォン、タブレット、または PC の画面を2人で見ながら、**Discover → Play** を押します。
2. 2人のニックネームを入力し、絵の付いた8種類のゲームから選びます。その種類の未プレイ活動がランダムに選ばれ、始める前に図で遊び方を確認できます。**Activities** からゲーム形式を選んで始めることもできます。
3. クイズでは画面に表示された人から順番に回答します。2人目が回答するまで正解を表示せず、2人分の回答がそろってから答え合わせをします。正解数はそれぞれ集計されます。
4. 会話カードでは同じお題について1人目、2人目の順に話します。話し終えた人がボタンを押し、2人が話し終えると次のお題へ進みます。
5. 最後のステップまで遊ぶとレビュー入力なしで **MISSION COMPLETE** が表示され、**+30 points** を獲得します。短い結果画面に Charlie の **+10 growth** も表示し、クイズでは2人それぞれの正解数も表示します。
6. **My circle** に活動名、2人の名前、クイズの正解数が保存されます。プロフィール未登録でも履歴の確認と特典交換ができます。

端末を渡し合っても、テーブルの上に置いて一緒に操作しても使えます。対面モードは年齢に関係なく利用できます。カメラや外部サービスは使いません。任意の音声返事を録音する場合だけマイク許可が必要です。途中のゲーム進行状況はメモリー内だけにあり、ページを閉じたり再読み込みしたりすると未完了の活動は消えます。完了した活動とポイントは最終ステップで自動保存されます。評価やメモの入力は必要ありません。

## Charlie のローカル週次ジャーニー

1. ホームで **Feed** を押すと、その日の世話として成長ポイントを 3 点獲得します。1 日 1 回までです。
2. **Open** を押すと、Charlie が今週の質問を表示します。質問はシンガポールの家族で話しやすい、遊び・食べ物・音楽・思い出などの内容です。
3. このローカル版では、同じ端末を祖父母に渡して **Reply** を開きます。返事は文章、または任意の音声メモで保存できます。マイクを使わない場合も文章だけで完了できます。
4. その週の最初の返事で Charlie が 15 成長ポイントを獲得します。完成したゲームは、クイズ、会話、ストーリーなど形式を問わず毎回 10 成長ポイントになります。ペットが弱ったり、連続ログインを逃して損をしたりする仕組みはありません。
5. 成長すると Charlie のレベルが上がり、部屋の飾りが増えます。**Characters** タブでは Charlie の成長状況と、活動プレビューに登場する架空のキャラクターを確認できます。Charlie はゲーム選択、遊び方、完了画面にも登場します。
6. **Print this month’s storybook** から今月のゲームと家族の文章をまとめた冊子を開き、ブラウザーで印刷できます。音声だけの返事は冊子に録音の記録が載りますが、音声データ自体は端末内に残ります。

ホームは Charlie・成長メーター・「遊ぶ／世話する」を中心に表示し、週次の質問と **TODAY’S GAME** を続けています。累計の活動・ポイントなどは **Your moments** を開くと確認できます。日替わりテーマのストリークとペットの成長は別の仕組みです。ペットの質問・返事・録音は同じブラウザー内だけで、遠くに住む祖父母の端末へ送ることはできません。端末間の招待、同期、リモート音声共有はサーバーを追加する将来段階です。

## レベル・HP・年齢別の学習と Pick Up Sticks

**Settings** タブの **Games & conversations** で年齢とチャレンジを設定します。ホーム・活動一覧・Characters・ゲーム開始画面には設定パネルを表示せず、保存した内容を次のクイズや会話へ自動で反映します。成長や解放条件の詳細は Settings 内の **Charlie’s progress & unlocked challenges** を開くと確認できます。Charlie は成長ポイント 40 ごとに 1 レベル上がります。

| Charlie のレベル | 選べるチャレンジ |
| --- | --- |
| 1 | First steps：クイズ4問・トーク4題、Pick Up Sticks 9本、棒のヒント |
| 2 | New adventures：クイズ5問・トーク5題、棒15本 |
| 4 | Master explorer：年齢別の全問題・全お題、棒21本 |

**Child’s age group** は、6〜8歳＝学習レベル1（色・数・身近な自然）、9〜11歳＝学習レベル2（数の規則・自然・地域）、12歳以上・大人＝学習レベル3（文化・推理）です。3種類のクイズに加え、Guided Talk・Random Talk・Would You Rather・Story Game・Then & Now・Walk with Charlie の各活動でも、年齢別に問題やお題が変わります。6〜8歳は好きな物・色・音・身近な体験、9〜11歳は理由の説明・比較・簡単な計画、12歳以上は文化・経験・世代の違いを掘り下げる内容です。Pick Up Sticks の本数は年齢には依存せず、Charlie のレベルで解放するチャレンジに応じて決まります。**Save settings** で保存します。2人プレイの開始時はプレイヤー名だけを入力し、年齢とチャレンジは Settings の選択を使います。プレイ中に学習レベルや年齢区分を表示せず、問題とお題そのものを切り替えます。プロフィールの年齢が初期値になり、プロフィールなしでは12歳以上のグループが初期値です。年齢区分はゲーム選択の目安であり、発達の評価ではありません。Charlie のレベルアップで年齢区分が勝手に変わることはありません。

クイズと Pick Up Sticks は各ゲーム **共有HP 3** で始まります。クイズの不正解、または下にある棒を取ろうとするとHPが1減ります。対面クイズのHPは2人目が回答した後に更新し、1人目の正誤は漏らしません。HPが0になったら **Recover**で回復し、同じ問題・棒の配置から続けられます。回復で報酬は増えません。HPと未完了の盤面はそのゲーム中だけ保持し、再読み込み時には初期化します。

Pick Up Sticks は **Activities → Pick Up Sticks → Play together / Try solo** から始めます。

1. 大きなテーブル上の棒、または **Choose by number** を開いた番号ボタンを選び、**Lift** を押します。**Zoom** で盤面をさらに拡大してスクロールでき、**Fit** で全体表示に戻せます。番号と選択中の棒を強調し、盤面上の棒はキーボードの Enter / Space でも選択できます。他の棒が上に重なっていない棒だけ取れます。
2. 黄1点、青3点、赤5点、黒25点を獲得します。2人プレイでは成功時は同じ人が続けられ、**Pass** で任意に交代できます。取れない棒を選ぶとHPを1失い、自動で交代します。
3. First steps の **Hint** は取れる棒を教えます。
4. 全部取ると棒の得点で勝敗を表示し、対面プレイは30 kindness points と Charlie の10成長ポイントを自動保存します。1人プレイは最後のレビュー保存時に加算します。棒の得点は交換用ポイントとは別です。
5. **My circle** に完了結果と得点が残ります。途中終了では報酬を加算しません。2人プレイはプロフィールなしでも使えます。

シンガポールの [Families for Life の伝統遊び紹介](https://www.familiesforlife.sg/pages/Activity/Blast-To-The-Past-with-Traditional-Games) を参考にしたデジタル版です。物理的に手で棒を動かす動作ではなく、重なりを観察して上の棒を見つけるゲームとして実装しています。棒の配置はゲームごとに変わり、スマートフォンやキーボードでは番号ボタンでも操作できます。外部サービスや画像のダウンロードは不要です。

## Charlie の進化

Charlie は成長ポイントに応じて見た目も進化します。ゲーム完了、毎日の世話、週次の最初の返事で境界を越えると、前の姿から新しい姿へ変わる演出が表示されます。

| 成長ポイント | 姿 |
| --- | --- |
| 0 | New friend：小さな葉の最初の姿 |
| 30 | Curious sprout：2枚の若葉と緑のスカーフ |
| 80 | Little explorer：探検帽とリュック |
| 180 | Story keeper：星の王冠、ケープと本 |

ホーム・ゲーム・Characters・ストーリーブックの Charlie は同じ成長状態を使います。従来の履歴から姿を決めるため、既存データの移行や作り直しは不要です。**Characters → Charlie’s journey → Replay evolution** で、獲得済みの進化だけを再生できます。再生・再読み込みでポイントや成長は増えません。端末の動きを減らす設定では変身アニメーションを省き、進化後の姿を表示します。

ピッチ素材の `demo/pitch/videos_phone/charlie-evolution.mp4` は、実際に18回の対面ゲームを完了して得た進化から、最初の変身を省いて後半2回を等速で抜粋した動画です。保存データの成長値やレベルを書き換えて撮影していません。

操作ボタンは原則1語、長くても2語に揃えています。スマートフォンでは下部ナビゲーション、縦1列の活動カード、大きめの文字と操作ボタンを使い、コミュニティのサンプル機能は折りたたんであります。推薦は説明可能なルールで動作します。**生成 AI・外部 LLM には接続していません。** 実際の通話、チャット、離れた端末からのレビュー収集、グループ内の交流、実店舗で使えるクーポンも未実装です。画面でも Community demo の人物・接続と特典がサンプルであることを明記しています。

プロフィールを作成する場合、6〜11 歳は必ず Family mode で、家庭内で一緒に遊ぶ体験になります。12〜17 歳も保護者関与の選択がなければ Family mode です。18 歳以上、または保護者関与を選択した 12〜17 歳は Community demo を使えます。この選択は本人確認や保護者同意の検証ではありません。世代の区切りはデモ用に 60 歳としています。対面モードは Family mode でも利用できます。

## Community demo の操作例

1. **Find your people** からプロフィールを作ります。例: `Alex`、16 歳、`Gardening` と `Games`。Community demo を試すときは保護者関与を選びます。
2. マッチ候補の **Preview** → **Start** で活動を開始します。
3. クイズは全問に回答、会話カードは全カードを進めて **Finish** を押します。
4. 評価と任意のメモを入力し、**Add … to my circle** を選んでレビューを保存します。30 ポイントが加算されます。
5. **My circle** で友だちと履歴を確認します。**Discover** のグループで **Join** を押すとグループも保存されます。
6. 活動をもう 1 回完了すると 60 ポイントになり、**Rewards** で最初のサンプル特典を交換できます。
7. 再読み込みして保存を確認します。プロフィールを 8 歳に変えると Family mode の活動を試せます。

同じセッションのレビューによる重複加算と、残高を超えた交換は防止しています。途中終了ではポイントを加算しません。デモの活動は繰り返し実行できます。

## 保存と削除

文章、ゲーム履歴、ポイント、プロフィール、ペットの成長、世話日、質問と返事はブラウザーの `localStorage`、キー `kindred.v1` に保存します。旧データ形式からの移行に対応しています。音声メモは `IndexedDB` の `kindred-local-voice-v1` に Blob として保存します。**どのデータも外部へ送信しません。** 分析タグ、CDN、外部フォントもありません。ブラウザーや URL のオリジンが変わると保存先も変わります。複数端末・利用者間の同期はありません。複数タブを同時に編集すると最後に保存した内容が優先されるため、同時利用は 1 タブを想定しています。

プロフィール設定画面の **Reset demo data** からプロフィール、ゲーム履歴、ペットの質問・返事・成長、音声メモ、ポイントをまとめて削除できます。ブラウザーのサイトデータ削除でも消せます。保存禁止や容量不足の場合は画面に警告し、その訪問中だけ動作します。現在のデータ形式と整合しない保存内容は空の状態として読み込みます。ペット追加前に保存したプロフィール・履歴も引き続き読み込めます。

## チームメイトにリンクを共有する

このリンクで配るのはアプリの画面とサンプル活動です。オンライン対戦や端末間の同期はありません。各自が別のスマートフォンで開いた場合、別々のアプリとして動き、ポイントや履歴も各自のブラウザーにだけ保存されます。2人で一緒に遊ぶときは、1台の画面を2人で見て操作してください。ニックネームも実名を避けてください。

手軽にリンクを作るなら GitHub Pages が使えます。ただし Pages のサイトは、リポジトリが非公開でもインターネット上で公開されます。身内だけにアクセスを限定したい場合は Pages を選ばず、CPU サーバーで HTTPS と VPN またはアクセス認証を使って `dist/` を配信してください。リンクを知っている人だけにする設定はアクセス制限にはなりません。

GitHub リポジトリの作成から push までのコマンドは [PUBLISHING.md](PUBLISHING.md) にまとめています。

## GitHub Pages で公開する

`.github/workflows/pages.yml` を同梱しています。`main` への push 時に静的チェックと既存テストを実行し、`dist/` のみを公開します。

1. GitHub でリポジトリを作り、このプロジェクトのファイルを `main` ブランチへ push します。
2. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
3. `main` への push で公開処理が始まります。手動の場合は **Actions → Publish GrandPals to GitHub Pages → Run workflow** を選びます。
4. 成功後、**Settings → Pages** または Actions のデプロイ結果に表示される URL をチームに共有します。通常は `https://<owner>.github.io/<repository>/` です。

ブランチ名が `main` 以外なら workflow の `branches` を変更してください。画像・CSS・JavaScript は相対パスで参照しているため、リポジトリのサブパスでも動きます。URL の画面切替には `#activities` などのハッシュを使い、サーバーの URL 書き換え設定は不要です。

GitHub Pages は静的ファイルを公開するサービスで、秘密のチーム用サイトにはなりません。[GitHub Pages 公開の説明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) と [GitHub Actions による公開手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) を参照してください。この作業では GitHub リポジトリの作成、push、外部公開はしていません。

## CPU サーバーで共有する

最も簡単なのは、既存の Web サーバーの公開ディレクトリへ `dist/` の中身をコピーする方法です。静的ファイルなのでアプリ用の GPU やデータベースは不要です。JavaScript を適切な MIME タイプで配信してください。

Node.js で短時間の共有確認をするなら、次の起動方法もあります。

```bash
node scripts/serve.mjs --host 0.0.0.0 --port 8080
```

その場合はアクセス可能なネットワーク上の端末から `http://<server-address>:8080` を開きます。付属サーバーは `dist/` だけを公開しますが、ログイン機能や HTTPS は持ちません。チームだけに共有するなら、CPU サーバー上の HTTPS 対応 Web サーバーまたはリバースプロキシの前に VPN / アクセス認証を設定してください。Node の付属サーバーをインターネットへ直接公開しないでください。ホストのファイアウォールや常駐設定は自動変更しません。

離れた端末の利用者同士をつなぐ段階では、CPU サーバー側に次を追加できます。

- アカウント、プロフィール、同意管理、アクセス権、共有データベース。
- セッション・友だち申請・双方のレビューを扱う API と、通報・ブロック機能。
- WebRTC の接続調整と STUN/TURN を含む実通話基盤。
- AI による推薦や会話テーマ生成。外部 API を使う場合の秘密鍵はサーバー側で保持。
- サーバーが管理するポイント台帳と、提携先が検証できる特典交換。

現在のブラウザー内のポイントや保護者設定はユーザーが変更できるため、本番の認可・交換処理には流用せずサーバーで検証する設計にします。

動画は無音のMP4 / H.264。各機能は5〜10秒の1倍速、棒拾いハイライトも1倍速で、全編のみ1.5倍速です。進化動画は最初の変身を省き、後半2回を収録しています。特典交換はギフト開封演出を含み、画像19が開封中、20が交換完了です。画像13は両サイズとも `13-charlie-home.png` です。動画のポスターは各画像フォルダーの `posters/` 内にあります。

元の録画と抜粋元の秒数は `demo/pitch/source/`、寸法・速度・アプリのハッシュは `manifest.json` に記録しています。実機撮影ではなく、Chromiumのスマホ表示・PC表示を操作して収録しています。Alex・Granと家族の返事、特典券は説明用のサンプルです。

再生成には **`scripts/refresh_pitch_kit.mjs`** を使います。任意のPlaywright・Chromium・FFmpegを `PLAYWRIGHT_MODULE`、`PLAYWRIGHT_BROWSERS_PATH`、`FFMPEG_PATH` で指定できます。アプリの実行時依存には追加していません。旧構成の素材は `demo/archive/` にまとめ、アーカイブ後もハッシュで一致を確認します。

特典交換にはギフト開封と色付きの紙吹雪を実装しています。特典動画だけの撮り直しは `scripts/refresh_reward_confetti.mjs`。交換確認から完了画面まで約9.5秒を収録し、録画中に画像撮影や画面移動を挟みません。全体再生成にもこの撮影手順を組み込んでいます。

**`demo/` 全体は `.gitignore` の対象です。** 共有・バックアップ時は必要なフォルダーを別途コピーしてください。
